# 2066 — AI-Native Autonomous Runtime

[![CI](https://github.com/dansya-arsana/runtime-2066/actions/workflows/ci.yml/badge.svg)](https://github.com/dansya-arsana/runtime-2066/actions/workflows/ci.yml)

**Status: 1.4 — Stages A–D complete: full-stack apps, capability
authority, multisig + delegation chains, MCP tools, reputation +
red-team verification. 335 tests green.**

2066 is not a programming language for humans. It is an AI-native semantic
execution layer: AI agents author **semantic graphs**, a deterministic
validator checks them, a mechanical repair loop fixes what it prescribed,
and the runtime executes the result directly — no JavaScript, Python, Rust,
or shell is ever generated. The canonical form has a deterministic SHA-256
identity, and the same program executes equivalently through two
independent adapters. Authority will live in capabilities and cryptography,
never in the model that proposed the program.

## Install

```bash
pip install runtime-2066
# or from source:
pip install .
```

The `2066` command is now available globally. Requires Python ≥3.12 and
the `cryptography` package (auto-installed).

## License

AGPL-3.0 — copyleft is the point. Anyone may run, study, and modify 2066,
but modified versions — including ones offered as a network service — must
release their source under the same terms. Improvements flow back or don't
flow at all.

The **name** and the **specification** are the identity: a modified runtime
that changes the grammar or semantics produces different canonical hashes
and must not be called 2066 unless it passes the project's conformance
suite. `runtime-2066` on PyPI is the canonical distribution.

## MCP server — give your AI agent 2066 tools

`pip install runtime-2066` ships an MCP stdio server. Point any MCP
client at it (Claude Desktop / Claude Code `claude_desktop_config.json`):

```json
{ "mcpServers": { "2066": { "command": "2066-mcp" } } }
```

The agent gets `2066_calculate` (pure, guarded arithmetic) plus a
capability-gated notes data plane (`2066_notes_register/login/add/get/
list`) with signed, expiring, revocable sessions. Session-mint keys live
in `~/.2066/mcp/` — never in site-packages.

## Quickstart

```bash
cd 2066

# hello world — direct semantic execution
python -m runtime run examples/hello.ai
# → Hello, World!

# first proof of concept (master roadmap §12): 10 × 5
python -m runtime run examples/arithmetic.ai
# → 50

# named subgraphs: call / param / return
python -m runtime run examples/call.ai
# → 42

# first public demo (§81): (100 * 1.05)^10, no loops — the multiply chain IS the program
python -m runtime run examples/compound_interest.ai
# → 1.6288946267774412e+20

# the repair loop (§13/§80): the sabotaged demo gets a structured E203,
# the runtime applies its own prescribed cast repair, and the fixed program
# produces the identical result
python -m runtime repair examples/compound_interest_error.ai > fixed.ai
python -m runtime run fixed.ai
# → 1.6288946267774412e+20

# canonical program identity (§15) — comments, whitespace, and field order
# don't exist here; the same program always hashes the same
python -m runtime hash examples/hello.ai
# → sha256:e6e0db153dac5968b2b21ef80f44a76d49f142f36dcc3ce827b044d726494ded

# engine independence (§102, Appendix F.3): the same program through a
# second execution adapter (compiled-plan stack VM instead of the
# tree-walking interpreter) — identical results, identical errors
python -m runtime run examples/compound_interest.ai --adapter plan
# → 1.6288946267774412e+20

# capability runtime (§17–§20, §82): scoped access allowed...
python -m runtime run examples/file_read.ai --caps examples/caps_demo.json
# → The runtime decides — not the model.

# ...out-of-scope denied (exit code 4, structured E401)...
python -m runtime run examples/capability_escape.ai --caps examples/caps_demo.json
# → ERROR E401 ... (exit=4)

# ...and default deny: no --caps means zero authority
python -m runtime run examples/file_read.ai
# → ERROR E401 denied: no capability system attached (exit=4)

# static effect manifest — what authority would execution need? (ask BEFORE running)
python -m runtime effects examples/file_read.ai
# → FILESYSTEM_READ / PURE / SYSTEM

# agent identity + signed grants (§26): keygen → sign → run verified
python -m runtime keygen agent.json --id agent-A91      # writes agent.key (secret!)
python -m runtime sign-caps examples/caps_demo.json --agent agent.json --key agent.key --out signed.json
python -m runtime verify-caps signed.json
python -m runtime run examples/file_read.ai --caps signed.json --require-signed
# → The runtime decides — not the model.
# (edit one byte of the signed file and the run refuses: fail closed)

# an interactive calculator — real stdin/stdout, guarded division, and a
# select-tree instead of if-statements (branch is a pure value select)
printf "12\n+\n3.5\n" | python -m runtime run examples/calculator.ai
# → a = op = b = result = 15.5
printf "10\n/\n0\n"  | python -m runtime run examples/calculator.ai
# → a = op = b = error: division by zero

# not just text: compute in the graph, emit HTML+CSS through a capability-gated write
python -m runtime run examples/calculator_page.ai --caps examples/caps_write.json
# → 670   (bytes written — open examples/out/calculator.html in a browser)

# export backend (§10): the same program lowered to standalone Python source,
# running OUTSIDE the 2066 runtime — identical behavior
printf "12\n+\n3.5\n" | python -m runtime run examples/calculator.ai > answer.txt
python -m runtime export examples/calculator.ai --target python --out calc.py
printf "12\n+\n3.5\n" | python calc.py
# → a = op = b = result = 15.5   (byte-identical; diff answer.txt to confirm)

# the real calculator APP: the engine is engine.ai compiled to JavaScript;
# the browser runs 2066-compiled code behind a full UI (keyboard, chained
# ops, error states)
python -m runtime export examples/calculator_app/engine.ai \
    --target javascript --library --out examples/calculator_app/engine.js
# then open examples/calculator_app/index.html in a browser

# FULL-STACK: notes app with SQLite database + password auth. All business
# logic is .ai programs (register/login/add_note/get_note) executed by the
# runtime with signed-capability grants; the server is a logic-free shell
python examples/notes_app/server.py
# → http://localhost:8618  (register → login mints an ed25519 session
#   token → token-gated notes; forged tokens denied; 0.9 ms/request)

# schema migration (§25): safe changes apply, destructive ones are refused
python -m runtime migrate examples/notes_app/add_note.ai --db notes.db

# hardening (this release): pin grant issuers, self-hash the runtime
python -m runtime run p.ai --caps c.json --trust-store issuers.json --require-signed
python -m runtime digest      # publish this; anyone can re-verify the runtime

# logout that means something: revoke every outstanding session of a user
python examples/notes_app/server.py --logout-user 1   # revokes minted tokens

# evidence (C.5): hash-chained audit of every privileged action
python -m runtime run prog.ai --db n.db --caps c.json --evidence audit.jsonl
python -m runtime evidence audit.jsonl     # verify the chain — tampering detected

# MULTI-AGENT (§29-§30, §83): agents propose signed node-level diffs; the
# runtime merges disjoint changes automatically and rejects conflicts
python -m runtime propose examples/proposals/agent_a_engine.ai \
    --base examples/proposals/base_engine.ai \
    --agent examples/proposals/keys/agent_a.json \
    --key examples/proposals/keys/agent_a.key \
    --out /tmp/a.json
python -m runtime merge examples/proposals/base_engine.ai \
    --proposals /tmp/a.json,examples/proposals/proposals/b.json

# 2066 runs .ai programs DIRECTLY — no compilation to another language
# ever happens (§12). For machines with no Python at all, a frozen
# standalone binary ships the runtime inside itself:
bin/2066.exe run examples/hello.ai          # Windows, zero dependencies
bin/2066.exe run examples/calculator.ai     # stdin, caps, --db all work

# rebuild it after changing the runtime:
python -m PyInstaller --onefile --name 2066 --distpath build/dist \
    --workpath build/work --specpath build build/entry.py

# ANY DISK = THE HUMAN KEY (§31-§33, §84): format an old flashdisk as the
# physical approval object, then approve scoped delegations with a PIN
python -m runtime key-format E:/ --id human-you          # non-destructive
python -m runtime approve wanted.json --key E:/ --ttl-minutes 5 --out ok.json
python -m runtime run examples/file_read.ai --caps ok.json --require-signed
# (expired after 5 min -> E402 denied; the §84 loop, achieved in software)

# machine-readable everything
python -m runtime run examples/arithmetic.ai --json
python -m runtime repair examples/compound_interest_error.ai --json

# deterministic test suite (177 tests, incl. a 2,000-node stress graph and
# node-verified JavaScript exports)
python -m unittest discover -v

# benchmarks: runtime overhead vs native, authoring size, verification cost
python benchmarks/benchmark.py   # results + analysis: benchmarks/RESULTS.md
```

`bin/2066` is a convenience wrapper: `./bin/2066 run examples/hello.ai`.

## What a 2066 program looks like

```text
func compound
node 101
op param
index 0
type f64
... (body)

main

node 001
op const
type i64
value 10

node 002
op multiply
input 001 001
output i64

node 003
op emit
input 002
```

One canonical way to write each construct (roadmap §8); the graph is the
source of truth (Constitution, law 10). Full grammar: [spec/graph.md](spec/graph.md),
instruction set: [spec/instructions.md](spec/instructions.md).

## Guarantees at this milestone

- **Deterministic**: same program ⇒ byte-identical output and errors, always
  (computation plane; the authority plane is time-based by construction —
  expiry needs a clock — and `--now` freezes it for tests).
- **Identifiable**: the canonical form carries a SHA-256 identity; formatting
  is not identity ([spec/graph.md](spec/graph.md)).
- **Engine-independent**: two execution adapters (tree interpreter, plan VM)
  produce identical results and identical errors — enforced by tests
  ([research/bootstrap_comparison.md](research/bootstrap_comparison.md)).
- **Capability-gated**: effects exist only behind explicit, scoped, expiring
  grants; no grants means zero authority; the instruction set has no op that
  can mint or widen authority ([spec/instructions.md](spec/instructions.md)).
- **Attributable**: grants can carry ed25519 issuer signatures that are
  verified fail-closed at load; tampering with a signed file refuses it
  entirely ([spec/identity.md](spec/identity.md)).
- **Total**: no undefined behavior — overflow, division, cycles, type
  mismatches, bad casts, denials are all structured errors ([spec/errors.md](spec/errors.md)).
- **Terminating**: DAG scopes + acyclic call graph ⇒ no infinite execution.

## Not (yet) on purpose

No wallets, Genesis, robots, or blockchain — master roadmap §77 and §102
explicitly forbid starting there. Next is M4b: the semantic data runtime
(Phase 6–7, SQLite behind `data.*` semantics with `data.read:User`-style
signed capabilities — AI never writes raw SQL), then multi-agent
collaboration (Phase 8–9).
