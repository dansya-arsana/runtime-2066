# Operations reference

All 24 built-in operations. Every operation declares its effect class;
`FILESYSTEM_*` and `DATA_*` operations require capabilities at runtime.
All operations except `emit` are pure computation.

**Effect classes:** `PURE` · `SYSTEM` (implicit grant — stdio) ·
`FILESYSTEM_READ` / `FILESYSTEM_WRITE` / `DATA_READ` / `DATA_WRITE`
(capability required).

---

## Values and dataflow

### `const` — PURE
Literal value. Fields: `type` (bool/i64/f64/string/bytes/null), `value`
(canonical literal). No inputs.

```text
node 001
op const
type f64
value 1.05
```

### `copy` — PURE
Identity passthrough; makes dataflow explicit. Input: any. Optional
`output` declaration.

### `concat` — PURE
String concatenation. Inputs: 2 strings → string. Chains compose documents.

### `cast` — PURE
Explicit conversion; `output` names the target type. Legal pairs:
`i64⇄f64`, `string→i64`, `string→f64`, `i64/f64/bool→string`, plus
identity. Failures: E303 (f64 not representable as i64), E304 (string not
parseable). No other conversions exist — there is no implicit coercion.

---

## Arithmetic — PURE

`add`, `subtract`, `multiply`, `divide` — 2 inputs, same type only
(`i64` or `f64`), `output` required.

- i64: truncating division; ÷0 → E301; overflow → E302.
- f64: IEEE 754, total (`1.0/0.0 → inf`, `0.0/0.0 → nan`).

## Logic — PURE

### `compare`
Fields: `mode` (`eq ne lt le gt ge`). Inputs: 2 same-typed values → bool.
Ordered modes require `i64`, `f64`, or `string`.

### `branch`
Inputs: `[condition: bool, if_true: T, if_false: T]` → T. Pure select:
**all inputs are evaluated**; only the choice is conditional. Arms must
share one type. There are no if-statements — compose cascades for
multi-way dispatch (see `examples/calculator.ai`).

---

## Functions — PURE

### `call`
Fields: `callee`. Inputs: one per parameter. Output: callee return type.

### `param`
Inside `func` only. Fields: `type`, `index` (0-based). No inputs.

### `return`
Inside `func` only, exactly once per function. Input: 1.

---

## I/O — SYSTEM (implicit grant)

### `emit`
Main scope only. Input: any. Prints the canonical rendering of its value;
batch channel, ordered by node id.

### `system.read`
No inputs → string. One line of stdin (no trailing newline). EOF → `""`.

### `system.write`
Input: string → i64 (chars written). Immediate stdout write, no newline
added — the interactive channel.

---

## Crypto — PURE

### `crypto.digest`
Field: `algorithm` (`sha256`). Input: string → string (hex).
Deterministic; the auth demo's password hashing.

---

## Filesystem — capability required

### `filesystem.read` — FILESYSTEM_READ
Input: path string → string (UTF-8 contents). Requires a grant
`filesystem.read:<path-scope>` covering the normalized path. Missing
files are E305; read limits (E403) are enforced after read, before the
value is usable.

### `filesystem.write` — FILESYSTEM_WRITE
Inputs: `[path, content]` → i64 (bytes written). Requires
`filesystem.write:<scope>`. Scope, expiry, and `max_bytes` are checked
**before** any byte is written.

---

## Data — capability required (§22–§24)

All data operations name an `entity` (declared with `entity { }`) and run
against the SQLite database attached with `--db`. All SQL is generated by
the runtime with bound parameters; unknown entities/columns are E501/E502
at validation time. Without `--db`: E401, always.

### `data.insert` — DATA_WRITE
Fields: `entity`. Inputs: one value per non-identity column, in
declaration order → i64 (row id). Requires `data.write:<entity>`.

### `data.count` — DATA_READ
Fields: `entity`, `where` (column name). Input: where value → i64.

### `data.select` — DATA_READ
Fields: `entity`, `column`, `where`. Input: where value → the column's
type. Returns the first match; absent rows yield the type's default
(`0`, `0.0`, `""`, `false`).

### `data.update` — DATA_WRITE
Fields: `entity`, `set` (column), `where` (column). Inputs:
`[new_value, where_value]` → i64 (rows changed). The identity column
cannot be updated (E503).

### `data.delete` — DATA_WRITE
Fields: `entity`, `where`. Input: where value → i64 (rows deleted).
Its **capability action** is `data.delete` — separate from `data.read` —
so a read-only agent cannot delete (§24).

---

## Capability quick table

| Operation | Required action | Resource |
|---|---|---|
| `filesystem.read` | `filesystem.read` | path scope |
| `filesystem.write` | `filesystem.write` | path scope |
| `data.insert`, `data.update` | `data.write` | entity name |
| `data.count`, `data.select` | `data.read` | entity name |
| `data.delete` | `data.delete` | entity name |
| everything else | none | — |

Errors: E401 denied (no grant) · E402 expired · E403 over limit ·
E305/E505 IO/data errors. Exit code 4 for any denial.
See the [Capabilities guide](capabilities-guide.md).
